# room-booking — сервіс бронювання аудиторій коледжу

HTTP-сервіс для обліку бронювань навчальних аудиторій, перевірки накладок у розкладі та пошуку вільних часових проміжків протягом дня.

## Призначення та цільова аудиторія

Сервіс призначений для диспетчерів розкладу, чергових адміністраторів та підрозділів коледжу (організація занять, консультацій, заходів в актовій залі та комп’ютерних класах). Програмний інтерфейс (REST API) автоматично блокує конфлікти бронювань, стежить за робочими годинами кожної аудиторії та обчислює доступні вікна під захід потрібної тривалості.

## Технології та структура проєкту

- **Платформа:** Node.js LTS, Express 5 (`express ^5.1.0`)

## Швидкий старт

1. Перейдіть у каталог проєкту та встановіть залежності:

```bash
npm install
```

2. За потреби створіть файл `.env` на основі `.env.example`:

```env
PORT=3000
MAX_BOOKING_HOURS=4
```

3. Запустіть HTTP-сервер:

```bash
npm start
```

Сервер запуститься за адресою `http://localhost:3000`.

## Маршрути API

| Метод і шлях | Опис | Параметри / тіло | Коди відповіді |
| --- | --- | --- | --- |
| `GET /api/rooms` | Список усіх аудиторій з `data/rooms.json` | — | `200` |
| `GET /api/rooms/:id/bookings` | Бронювання аудиторії на дату | query `date` (`"РРРР-ММ-ДД"`) | `200`, `404` |
| `GET /api/rooms/:id/free` | Вільні проміжки аудиторії | query `date`, `min` (хв, за замовчуванням `45`) | `200`, `404` |
| `POST /api/bookings` | Створення нового бронювання | JSON `{ roomId, date, from, to, who }` | `201`, `400`, `404`, `409` |
| `DELETE /api/bookings/:id` | Скасування бронювання | path `id` (числовий код) | `204`, `404`, `409` |

## Правила бронювання

- **Робочі години:** час початку й кінця має повністю входити в інтервал `[opens, closes]` конкретної аудиторії (наприклад, `101`: `08:00–18:00`, `204`: `08:30–20:00`, `aula`: `09:00–17:00`).
- **Максимальна тривалість:** не більше `MAX_BOOKING_HOURS` годин (за замовчуванням `4` години).
- **Напіввідкриті інтервали:** перетином вважається наявність спільного часу (`a.start < b.end && b.start < a.end`); суміжні бронювання `10:00–11:20` і `11:20–12:40` не конфліктують.
- **Мінімальний строк скасування:** бронювання дозволено скасувати не пізніше ніж за `2` години (`MIN_CANCEL_HOURS = 2`, версія 1.2.0 у `CHANGELOG.md`) до часу його початку.

## Відомі обмеження

- **Зберігання в пам’яті процесу:** усі створені бронювання існують лише під час роботи процесу Node.js і зникають після перезапуску; зміни до `data/rooms.json` не зберігаються.
- **Відсутність автентифікації:** API не перевіряє токен чи роль користувача; будь-хто з мережевим доступом може створювати й скасовувати бронювання.
- **Локальний час сервера:** обчислення моменту початку (`new Date("${date}T${from}:00")`) спирається на часовий пояс операційної системи, на якій запущено сервер.
