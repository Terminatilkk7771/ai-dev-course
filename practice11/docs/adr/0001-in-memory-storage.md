# ADR-0001: Зберігання бронювань у пам’яті процесу

- **Статус:** Прийнято (діє у версіях 1.0.0–1.2.0)

## Контекст

Сервіс `room-booking` розробляється як компактний API для розкладу аудиторій коледжу без зовнішніх баз даних у `package.json` (`express` є єдиною runtime-залежністю) та зі статичним списком аудиторій у `data/rooms.json`. Для тестів (`tests/api.test.js`) важливо швидко створювати ізольовані екземпляри застосунку `createApp()` без підготовки дисків чи СУБД.

## Розглянуті варіанти

1. **Масив у пам’яті процесу (`const bookings = []` у замиканні `createBookingService`)** — нуль зовнішніх залежностей, миттєве скидання стану між викликами `createApp()`.
2. **Файл JSON на диску** — зберігає дані після перезапуску, але ускладнює паралельні тести та потребує блокувань під час одночасного запису.
3. **Вбудована або окрема СКБД (SQLite / PostgreSQL)** — забезпечує персистентність і транзакції, проте вимагає схеми БД, міграцій і додаткових залежностей.

## Рішення

Обрано **варіант 1**: зберігати активні бронювання в локальному масиві `bookings` всередині `createBookingService` (`src/bookings.js:68`).

## Обґрунтування

У `package.json` відсутні драйвери БД, у `CHANGELOG.md` немає вимог щодо збереження між перезапусками, а кожен тест у `tests/api.test.js` викликає `createApp()`, розраховуючи на порожній ізольований стан бронювань. `Припущення:` на поточному навчальному етапі прототипування пріоритетом є простота розгортання та швидкість автотестів, а не довготривале збереження історії.

## Наслідки

- **Позитивні:** нульові витрати на інфраструктуру, ізольоване модульне й інтеграційне тестування без очищення БД, миттєвий відгук операцій.
- **Негативні (зокрема ризики на майбутнє):**
  - повна втрата всіх бронювань при будь-якому перезапуску або збої процесу Node.js;
  - неможливість запуску кількох реплік сервера (горизонтального масштабування), бо кожен процес матиме власну ізольовану копію масиву `bookings`;
  - відсутність історичного журналу скасувань (при `cancel` запис фізично видаляється через `splice`), `Припущення:` за потреби аудиту доведеться впроваджувати БД і м’яке видалення (soft delete).
